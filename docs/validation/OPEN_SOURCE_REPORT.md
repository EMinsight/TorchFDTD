# Open-source CUDA measurements

Measured 19 September 2026 on NVIDIA RTX 5880 Ada Generation, 48 GB, Windows 11 Pro build 26100. Python reports the OS as `Windows-10-10.0.26100-SP0`. The CPU is Intel Xeon w3-2435. The comparison used Torch 2.10.0 with CUDA 12.8, NumPy 1.26.4, CuPy 13.6.0, fdtd 0.2.2 and NVIDIA driver 581.80. The live UI was idle. No other benchmark was launched on this GPU during measurement.

## Common physical inputs

The domain is a 4.8 µm cube in air. Structures are a radius-0.5 µm sphere, a 0.3 µm slab extending across y/z, or an x-directed 4.8 × 0.6 × 0.4 µm dielectric guide. The non-vacuum material index is 1.5. The source is an Ez soft electric point source at (-1.2, 0, 0) µm, with central wavelength 1.55 µm and two-cycle Gaussian scale. The Ez point monitor is at (1.2, 0, 0) µm. Both engines receive the same source samples and component-specific voxel permittivity. The guide fixture is a point-driven field propagation test, not a modal transmission calculation.

All measurements use real float32, 800 steps and CFL factor 0.99. The PML has eight cells per face at 64³/96³ and four at 32³. Sigma is cubic, kappa is one and alpha is 1e-8. Automatic decay termination and periodic divergence diagnostics are disabled in every timed mode. The batch radius varies as 0.35 + 0.01i µm. Higher resolution changes physical timestep and duration in these fixed-step throughput tests. They are not resolution-convergence comparisons.

## Baseline and timing fairness

`benchmarks/open_source.py` calls the installed, unmodified `fdtd.Grid.update_E` and `update_H`. The graph adapter supplies the same external source/trace operations and resets every field and PML state after graph warmup/capture. The adapter's final E/H and traces agree bitwise with upstream eager execution in all eight fixtures. No commercial source, structure file or simulation output enters these fixtures.

Each mode gets one warmup. Three timed repetitions alternate mode order. Full wall time covers geometry setup, array allocation, graph preparation, time stepping, the full E/H result transfer and result construction. The batch measurements also evaluate the trace-peak objective. Cold interpreter, initial CUDA context, first kernel compilation and file saves are excluded. Process baselines additionally exclude worker startup and include dispatch, IPC and worker allocator cleanup. Native graph and upstream graph use the same numerical workload and source/point outputs. Native runs additionally construct their normal final display/result data.

Host scheduling and WDDM contribute variability. These are medians of three repetitions, not confidence intervals or claims about peak hardware throughput. In particular, the single-case upstream graph times vary more than the native kernel loop. Raw minimum/maximum values should be consulted for a different deployment or a performance decision. Re-run with more samples for statistical inference.

Torch `max_memory_allocated` excludes driver/context allocations and memory outside Torch. A process worker's memory cannot be inferred from the parent's Torch allocator. No process-memory comparison is reported.

## Accuracy scope

The predeclared acceptance threshold is point-trace relative L2 below 1%. The upstream high-side electric PML interface omits a derivative that the native CPML includes. Thus matched physical profiles do not make the two discretizations identical. The eight single-case differences are 0.0120–0.0372%. The 32³ ensemble's largest trace difference is 0.2667%. Every recorded trace passes the stated gate.

Full E/H differences are retained, not treated as passing a 1% field criterion. For vacuum at 64³, final H has relative L2 difference 0.314542, maximum absolute difference 1.88582e-7 and reference peak 1.22583e-7 in reduced units. Late-time weak-field normalization explains why a small absolute difference can produce a large relative value, but does not establish that the boundary error is harmless for every observable. This comparison is insufficient to claim equivalent resonant Q, modal transmission or absorption accuracy. The native analytic slab and convergence tests are separate evidence.

Every tensor-batch E/H and point trace matches the native independent fused solve bitwise for the measured B=1/2/4/8/16 cases. Cohort splitting also preserves this agreement. Separate regression tests cover float64, 2D, graded metrics, periodic boundaries, multipole materials and planar DFT. Those are correctness checks, not timed cross-library dispersion benchmarks.

## Measured advantages and unresolved work

- Against graph-adapted flaport/fdtd: 9.64–17.09× shorter full wall time on the eight forward fixtures. Peak Torch allocation falls by approximately 60–66%.
- Against native sequential fused CUDA: 2.40× higher full-wall throughput at 32³, B=16. The same cohort is slower at 64³. The follow-up's four-by-four split improves 64³ full wall time by 1.10× against sequential and 1.43× against one 16-case cohort, with unchanged fields.
- Against FDTDX, fdtdz and fdtd3d: **no measured speed advantage established**. FDTDX already has adjoint/autodiff, dispersed anisotropic materials and rectilinear grids. We must not describe those as unique native features.

The RTX 5880 host currently has no WSL/Linux CUDA environment. Firmware virtualization and WSL platform features were observed disabled. [JAX's official platform table](https://docs.jax.dev/en/latest/installation.html#supported-platforms) does not support native-Windows NVIDIA GPU execution. fdtd3d additionally needs a compatible native compiler/build environment, and its reviewed source has POSIX dependencies. These are current environment limitations, not proofs that competitors are slow or generally unsupported.

Remaining benchmark work is to execute pinned FDTDX/fdtdz/fdtd3d on the same GPU under a compatible environment, validate each adapter's boundary and source semantics, and compare common observables at matched error. FDTDz's restricted domain and absorber need a separate compatible fixture. Gradient runtime and memory require a validated native adjoint first. GPU profiling and measured cohort selection remain follow-up optimization work.

## Reproduce

```sh
python -m pip install -e ".[cuda-kernels]"
python -m benchmarks.open_source --sizes 64 96 --steps 800 --repeats 3
python -m benchmarks.tensor_batch_validation
python -m benchmarks.cohort_validation
python -m pytest tests/test_tensor_batch.py tests/test_cuda_kernels.py
```

Install the appropriate CUDA-enabled PyTorch build before the extra. Raw runs are written under `results/open-source/`. Copy verified records into `docs/validation/` before regenerating the README. The new cohort wrapper was added after the full batch sweep and was measured separately in `cohorts.json`. The original ten-setting record is preserved unchanged.
