# Independent FSP scene import

Version 0.4 converts a verified subset of v241 layout-mode FSP settings into an editable native CPU/CUDA scene. Reading, conversion and native execution do not load Lumerical or require its license. This is an additional path alongside the broader licensed inspector and the loss-preserving binary reader. It does not complete the full replacement objective.

## Workbench and Python

Choose **FSP → GPU**, select a layout FSP, and review the object-specific diagnostics. **Open converted scene** becomes available only when every object has a supported mapping. Edit the imported objects and source time settings, then Run. Download original FSP retains its exact bytes. The original SHA-256, coordinate origin and calculation differences remain in saved native JSON, Python exports and NPZ project metadata.

The **FSP inspect** button and opening an FSP through the general Open control continue to use the licensed property inspector. The independent **FSP → GPU** path supports **Export current scene**. This writes supported existing-object and scene-setting edits into a new FSP using the original import as its immutable base. The original file remains downloadable separately.

```powershell
torchfdtd fsp-convert input.fsp --output scene.json --report conversion.json --backend cuda
torchfdtd run scene.json --output results/imported.npz
torchfdtd fsp-write-geometry input.fsp scene.json --output edited.fsp --report write-report.json
```

Output files must be new paths. A blocked conversion writes its report and exits with code 2, without writing a partial runnable scene.

```python
from torchfdtd.fsp_binary import FspDocument
from torchfdtd.fsp_native import convert_fsp
from torchfdtd import Simulation

conversion = convert_fsp(FspDocument.load('input.fsp'), backend='cuda')
if conversion.project is None:
    raise ValueError(conversion.issues)
result = Simulation(conversion.project).run()
```

## Mapped settings

| Family | Current mapping |
| --- | --- |
| Region | One top-level 2D XY or 3D FDTD region, constant real scalar background index |
| Mesh | Saved uniform isotropic or anisotropic grids, and saved auto/custom nonuniform nodes with staircase selection. Verified CAD/PML bounds, conservative stored timestep and maximum duration. Nonuniform nodes are frozen, not regenerated by the original mesher |
| Boundaries | PML layers per face, paired Periodic and paired Bloch boundaries (saved `BCType` 0, 1 and 5; Metal and symmetry codes are unverified and rejected). Duplicate cyclic boundary planes are removed. The Bloch phase per period comes from the saved `kx/ky/kz`: `blochUnits` 0 stores k·span/2π (bandstructure units, phase = 2πk), 1 stores rad/m (phase = k·span); `blochBasedOnSource` gives a zero phase with a warning because only normal-incidence paired sources are mapped. Native fields obey F(r+L) = exp(+iφ)F(r), the documented Lumerical relationship; the sign is not measured against vendor fields |
| Geometry | Boxes, elliptical cylinders/ellipsoids, full or partial elliptical rings and simple polygon extrusions. Three ordered fixed-world rotations, stored polygon pivot, enabled state and mesh priority. Object-defined dielectrics or supported database materials. Hierarchies and general solids remain unmapped. Structure groups with a setup script: the saved objects the script last generated are imported as ordinary structures (translated by the group; rotated groups are rejected), those entirely outside the region are omitted, the script is never executed, and such objects are not written back |
| Materials | Isotropic Dielectric, Plasma and Lorentz database records, supported passive coefficients, color and database/object mesh priority. Sampled-data records (type 7) are fitted from their embedded samples with `torchfdtd.material_fit.import_material_table` over the union of the global source range and every enabled local source range, root level or inside enabled analysis groups (extended outward to the neighbouring samples); the pole count and normalized RMS are reported as a `material_fit` warning and Lumerical's own fit coefficients are not reused |
| Source | Standard Gaussian, automatic wavelength/frequency range, manual broadband chirp, or saved user time/amplitude/phase electric dipole with a signed Cartesian axis or arbitrary theta/phi orientation. Local/global temporal settings, amplitude, phase and endpoint taper. Recognized 3D normal-incidence plane and closed TFSF sources map direction and linear polarization to native paired E/H injection. Enabled analysis groups contribute their enabled members (sources, monitors) as ordinary objects with their stored global coordinates; disabled groups are skipped, group scripts are informational, and a group whose members would exceed the native 32-source or 32-monitor limit is an error naming the group |
| Time monitor | Full-duration point E/H components, nearest-cell selection (specified-position interpolation is reported and replaced by the nearest Yee sample), every timestep. Multiple selected components become named native point outputs |
| DFT monitor | Point E/H traces and axis-aligned planes. Uniform frequency/wavelength, Chebyshev-Lobatto or custom samples. Local/global frequency settings with independent None/Full/Start/End apodization. Selected E/H/P and signed flux, saved temporal/axis strides, nearest normal-node or specified-plane interpolation, optional complex128 accumulation. Spectral averages, volume and uncollocated outputs are rejected |

The simulation origin is translated to the centre of the total computational extent, including asymmetric PML. For example, the measured 2D fixture with 10/14 x-PML layers maps to 104×40×1 native cells and shifts the origin by +0.1 µm. Its repeated y period remains 2 µm. The FSP's stored mesh must agree with its current settings, rather than treating a stale cache as authoritative.

## Explicit numerical differences

- Lumerical PML profiles are not copied into native CPML coefficient fields. Layer counts and extents are retained and the native coefficient convention is reported.
- Material placement on staggered Yee components and monitor sampling differ. The imported staircase geometry is not conformal/subpixel meshing.
- Source injection uses reduced fields, not a calibrated physical dipole moment. Absolute E, radiated power and source normalization are not interchangeable.
- A standard Gaussian uses `sin(-2*pi*f*(t-offset)+phase) * exp(-0.5*((t-offset)/sigma)^2)`, with `sigma = pulselength/(2*sqrt(log(2)))`. Phase is entered in degrees. Version 0.6 maps the saved endpoint-taper flag and [measured automatic/chirped definitions](BROADBAND.md).
- Native runs use the full maximum duration. If the FSP requests early shutoff, its omission is reported. Native nonfinite-field checking does not reproduce the vendor energy threshold.
- Native DFT returns unnormalized field integrals and signed reduced flux. Saved strides are retained, but quadrature positions, time-sample phase and source normalization are not identical to vendor outputs. Conversion diagnostics state these differences.

Automatic pulse parameters and standard/chirped selection must agree with the saved settings. Eliminate-DC processing, FSP magnetic dipole type mapping, oblique/finite-aperture and mode sources, anisotropy, conformal meshes, nested groups, rotated group transforms, script execution, automatic structure extension through PML, volume/time-distributed monitors and result-bearing files require further implementation. Saved rectilinear nodes do not reproduce the original mesh generator. Editing geometry leaves these nodes unchanged. TFSF import additionally requires constant spacing along each axis throughout its injection support. See [rectilinear controls and tests](RECTILINEAR_MESH.md).

Unsupported content is listed, not thrown. Objects that are left out without blocking execution are warnings: model setup/analysis scripts (the saved layout they last produced is imported), object classes without a mapping such as index monitors, disabled analysis groups, nested groups, disabled sources or monitors with unmappable settings, and z-normal frequency planes in 2D. Unsupported physics on an enabled, mapped object stays an error: an unmappable region such as a boundary code other than PML, Periodic or Bloch (`region_mapping`, with the stored codes), a rotated structure group, or an enabled source/monitor setting without a mapping (`object_mapping`), or an enabled analysis group whose members exceed the 32-source/32-monitor limits. Analysis-group members and script-generated objects carry `script_generated` in their conversion mapping and are never written back to the FSP: the geometry export keeps them unchanged, the scene-settings export refuses them. When the region itself cannot be mapped, structures, sources and monitors are not checked and a warning says so. When no enabled ranged source is imported, monitor source limits are replaced by the explicit global source range and a `monitor_source_limits` warning records it.

## Independent geometry writeback

```python
from torchfdtd import write_fsp_geometry
from torchfdtd.fsp_binary import FspDocument
from torchfdtd.fsp_native import convert_fsp

original = FspDocument.load('input.fsp')
conversion = convert_fsp(original, backend='cuda')
if conversion.project is None:
    raise ValueError(conversion.issues)
project = conversion.project
project.structures[0].center = (0.2, 0.0, 0.0)  # micrometres
project.structures[0].rotation_axes = ('x', 'y', 'z')
project.structures[0].rotation_angles = (17, 31, -29)  # degrees
edited, report = write_fsp_geometry(original, project)
edited.save('edited.fsp')  # exclusive creation, no overwrite
```

The writer requires the original SHA-256 and coordinate origin retained in the native project. It supports existing primitive position, dimensions, radii, ring angles, polygon vertices, three rotations, name, enabled state, mesh order and constant real dielectric assignments. Unchanged imported dispersive materials remain byte-identical. New dispersive coefficients are not written. Unicode names and changed polygon vertex counts may shift subsequent record offsets, so the report records both original and output ranges. Unedited byte segments, opaque fields, material records and unknown properties are copied exactly. A no-op export preserves the whole file byte for byte.

Polygon storage contains global unrotated XY vertices and a separate XY pivot. Conversion subtracts that pivot and restores it on export. One repeated closing vertex is accepted on import and retained by a no-op export. Rotations apply around the solid pivot in fixed-world order 1, 2, 3. Ring sectors use physical polar angle, including sectors crossing zero. If a native legacy z rotation precedes the three ordered rotations, export folds the complete matrix into an equivalent XYZ representation and reports that change. It does not discard the fourth rotation.

Every candidate is reparsed and converted again, checking geometry, material response, object classes and PML support. Unknown metadata forms and unsupported physical changes are rejected before a downloadable file is exposed. Backend, precision, snapshot and view choices belong to native execution and are listed as native-only in the report. This geometry-only API rejects source/monitor/region and object-list edits. The scene-settings writer below supports a defined subset, including [primitive addition, deletion and reordering](FSP_OBJECTS_WRITE.md). In-place primitive type changes and hierarchical geometry remain future work. Keep the native JSON project to retain the full edited simulation.

Author-generated fixtures in `tests/test_fsp_geometry_write.py` cover all five primitives, nonzero pivots, ordered rotations, closed contours, variable-length edits, missing ellipse extension properties, unknown-byte preservation, invalid metadata, CPU/CUDA and shared tensor cohorts. The UI test edits a polygon, downloads the verified file, reimports it and executes it on the native GPU. These tests establish the stated native subset, not general compatibility or electromagnetic agreement with a commercial engine.

## Independent scene-settings writeback

`write_fsp_scene(original, project)` extends the geometry writer with a checked subset of source, monitor and region edits. Mapped primitive, source and monitor lists may be changed, including [component-level monitor separation](FSP_INSTRUMENTS_WRITE.md). Saved nodes remain fixed unless a supported uniform mesh edit is requested. The old `write_fsp_geometry` API and `fsp-write-geometry` command retain their geometry-only contract.

```sh
torchfdtd fsp-write-scene input.fsp scene.json --output edited.fsp --report write-report.json
```

| Record | Supported edits |
|---|---|
| Electric dipole | Position, orientation, amplitude, phase, name and enabled state |
| 3D normal-incidence plane/TFSF | Supported position/spans, Cartesian axis, direction and transverse polarization |
| Source time settings | Standard Gaussian, automatic frequency/wavelength ranges, manual broadband and local sampled time/amplitude/phase tables. Supported local/global temporal inheritance |
| Frequency planes | Position/spans/normal, selected fields/Poynting/flux, precision, interpolation, spatial stride, frequency/wavelength/Lobatto/custom samples and local Gaussian apodization |
| FDTD region | Duration, CFL, recognized explicit-grid dt override, background index, valid existing-profile PML layer counts and paired PML/Periodic transitions |
| Uniform target mesh | Active-axis spacing, total region spans, controlling uniform selection, CAD/PML bounds and saved nodes. Smaller fixed dt is encoded through effective CFL. [Conventions and limits](FSP_MESH_WRITE.md) |
| Source/monitor lists | Add/delete/duplicate/reorder mapped records, split shared point components, preserve opaque template properties and map output IDs. [Scope and examples](FSP_INSTRUMENTS_WRITE.md) |
| Primitive list | Add/delete/duplicate/reorder the five mapped primitive families, with exact retained-byte ranges and remapped IDs. New records use authored metadata defaults, whose external-reader acceptance is unverified. [Object-list scope](FSP_OBJECTS_WRITE.md) |

Changes update controlling input properties as well as resolved values. Missing recognized properties can be appended without replacing unknown entries. Temporal DFT stride is encoded through local sampling-rate controls and reported as subject to the external source Nyquist limit. A reader may select finer sampling. Enabled sampled sources require stride 1 in this writeback subset. Frequency-based interior Chebyshev roots are represented by exact custom frequency tables. Wavelength-based roots and source-limited root conversions are not established by this subset.

Stored PML profile limits are enforced. Recognized stretched-coordinate profiles require even layer counts in this writer. Native CPML coefficient conventions are different and edited coefficients are rejected. These guards do not establish universal behavior for every file version. Boundary edits update the controlling boundary choice and preserve the native physical grid.

Global native apodization is flattened to each monitor's effective local window and disclosed in the export report. The native JSON retains its dynamic link. Inactive local frequency settings under global inheritance are not all represented. Changing point-monitor FFT/time-window postprocessing is rejected. Components sharing one original point record can be separated when their position, timing, name or order diverges. Split templates preserve opaque property encodings without interpreting their references.

Unmapped source/monitor classes, group hierarchy, new dispersive coefficients, graded/explicit mesh-generator export, magnetic FSP source types, cycle-based and continuous temporal definitions, and general settings/version compatibility remain open. Native execution backend, display, snapshots and auxiliary incident-line settings stay in JSON and are disclosed in the report. Export reparses the candidate and compares supported geometry, material, pulse, grid and spectral semantics before returning bytes. Author-generated tests in `tests/test_fsp_settings_write.py` exercise Python, CLI, HTTP and native CPU/CUDA roundtrips. Uniform remeshing is covered by `tests/test_fsp_mesh_write.py`, including input controls, node formulas, unchanged bytes and field/DFT checks. `tests/test_fsp_objects_write.py` covers list reconstruction, material reuse, overlap priority and object/component ID mapping. Browser tests edit, export, reimport and run authored scenes on the native GPU. External reopening/remeshing has not been verified.

## Native source controls

All native projects can now set the CFL factor. Sources expose **time definition**, **pulselength (power FWHM)**, **offset** and **phase**. Existing projects retain their cycle-based Gaussian convention and positive-time carrier. Standard time-domain inputs use the centred negative-time carrier above. Continuous sources retain a smooth turn-on with the selected width and ignore Gaussian offset. The familiar facade supports `set time domain`, `pulselength`, `offset`, `frequency`, `phase` and `dt stability factor`, with time in seconds.

Source time arrays are prepared once and copied to CUDA. Each captured time step reads the current sample on-device. Preparation time belongs to setup time, not solver-loop time.

## Dispersive database materials (v0.7)

Isotropic Dielectric, Plasma and Lorentz records are independently mapped by material UUID, with matrix checks, passive parameter validation, display color and database/object mesh priority. Native CPU/CUDA runs use trapezoidal ADE. Unknown types and anisotropy block conversion. This does not add general material fitting or material writeback. See [material definitions and limitations](MATERIALS.md).

## Vector electric dipoles (v0.12)

Recognized electric source records now map arbitrary theta/phi orientation. Synthetic imports retain original bytes and execute native vector fields. Axis-aligned legacy phase conventions are preserved. Native magnetic sources are implemented, but their FSP type code remains unverified and rejected. Source moment/power calibration remains open. Existing electric-dipole settings are covered by the scene writer above. [Definitions and tests](DIPOLE_SOURCES.md).

## Paired sources and selective plane spectra

Paired-source import is restricted to 3D normal incidence. A plane must cover the transverse periodic cell. A TFSF box requires a homogeneous nondispersive shell and external PML. The native auxiliary Yee line retains propagation delay and numerical dispersion. Amplitude scales its soft drive and is not a calibrated incident field. Synthetic axis/direction/polarization tests verify the implemented mapping. FSP 2D polarization conventions and absolute power remain open.

Imported Chebyshev grids use Lobatto endpoints. Native projects may alternatively choose interior roots. Global frequency settings remain dynamically editable while imported apodization stays local. Source-limited monitors require explicitly ranged enabled sources and follow their union when edited. Arbitrary custom tables take precedence over source limits.

Output dependency selection, accumulation precision, sampling times, decimation limits and reference normalization requirements are documented in [CUDA spectra](CUDA_SPECTRA.md). A flux-only plane accumulates four tangential fields internally and exports flux. It cannot later provide incident-field subtraction unless those fields were also selected for storage. Original FSP bytes remain unchanged throughout import, native editing and execution. The native projection does not establish general version compatibility. Explicit scene export supports only the verified subset above.
